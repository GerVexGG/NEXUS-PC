# AURORA 2.0.0

Системная утилита для Windows x64. Обзор показывает загрузку ресурсов и историю замеров с этого компьютера. Из него можно перейти к датчикам, процессам, накопителям, диагностике сети и инструментам обслуживания. Поиск раздела открывается сочетанием Ctrl+K.

## Установка

1. Подготовьте Windows 11 x64 с Microsoft Edge WebView2 Runtime. Для аппаратного мониторинга нужен Microsoft .NET Runtime 10 LTS x64. Версию среды можно проверить командой `dotnet --list-runtimes` (строка `Microsoft.NETCore.App 10.0.x`).
2. Запустите `AURORA_2.0.0_x64-setup.exe`. Установщик NSIS регистрирует приложение для текущего пользователя. После установки откройте AURORA через меню «Пуск».
3. Закрытие главного окна скрывает его в трей. Команда «Открыть AURORA» возвращает окно, «Выход» завершает программу. В настройках отдельно включаются запуск вместе с Windows и скрытие окна при таком запуске.

## Переход с NEXUS PC

AURORA использует самостоятельный идентификатор `com.gervex.aurora`, отдельную папку установки и ярлык. Прежний NEXUS PC можно оставить установленным.

- При первом обращении к настройкам, библиотеке скриптов и журналу событий приложение копирует соответствующий файл из `%APPDATA%\nexus` в `%APPDATA%\AURORA`, если копии ещё нет. Существующие файлы профиля AURORA имеют приоритет. При ошибке формата настройки и скрипты остаются доступны для ручного восстановления.
- Разрешение на автозапуск хранится в реестре Windows. Включение переключателя AURORA заменяет распознанную старую команду NEXUS в разделе `Run`. До этого пользователь может продолжать пользоваться автозапуском прежнего приложения. При конфликте с неизвестной командой настройка показывает ошибку.
- Учёт зарезервированной операции питания, резервная копия сетевого оптимизатора и записи отключённой автозагрузки используют совместимые пути предыдущих версий. Изменяйте общие настройки системы в одном экземпляре приложения за раз.
- Новые файлы AURORA Drop сохраняются в `%LOCALAPPDATA%\AURORA\Drop`. Ранее полученные файлы остаются в папке `NexusDrop` рядом со старым приложением или в `%LOCALAPPDATA%\nexus\NexusDrop`. Архивы остаются по выбранным пользователем путям.

## Архитектура

Приложение разделено на три слоя:

1. **Frontend (`src/`, React 19 + TypeScript + Vite + Tailwind CSS 4 + Framer Motion)**
   - Контроллер состояния (`src/hooks/useNexusController.tsx`), изолированные хуки сканирования, автозагрузки, очистки и таймеров питания.
   - Построение и фильтрация дерева процессов (`src/lib/processTree.ts`), форматирование метрик и валидация лимитов (`src/lib/metricsFormatters.ts`).
2. **Backend (`src-tauri/src/`, Rust Edition 2024 + Tauri 2)**
   - Аппаратная и системная телеметрия через Win32 API / `sysinfo` / DXGI / Windows PDH, ведение кольцевого буфера истории и диагностика (`telemetry.rs`).
   - Жизненный цикл фонового sidecar (`hwmon_watchdog`) с проверкой устаревания сэмплов и ограничением числа автоперезапусков.
   - Управление процессами с верификацией `PID + start_time + name` и защитой критических системных процессов Windows.
   - Инструменты накопителей: параллельный сканер томов с изоляцией операций отмены (`StorageScanCoordinator`), очистка системных кэшей с защитой профилей браузеров, нативный Win32 IOCTL S.M.A.R.T. с объединением с PowerShell fallback по `DeviceId` и серийному номеру (`storage_smart.rs`).
   - Сетевой стек (`net_monitor.rs`, `net_optimizer.rs`): адаптеры `GetAdaptersAddresses`/`GetIfTable2`, ICMP/TCP-пинги, UDP DNS-бенчмарк, резервное копирование и транзакционный откат параметров реестра/адаптера.
   - Локальный сервер передачи файлов (`drop_server.rs`) с криптографическим токеном сессии, rate-limit, квотами на размер файла/сессии и очисткой `.part`-файлов.
   - Планировщик питания (`power_manager.rs`), потоковый упаковщик классического 32-битного ZIP и интеграция с WinRAR CLI (`archive.rs`), runner пользовательских сценариев с таймаутами, усечением вывода и RAII-очисткой (`scripts.rs`).
3. **Hardware Sidecar (`hwmon-sidecar/`, C# / .NET 10 LTS)**
   - Установленный процесс `aurora-hwmon.exe` на базе `LibreHardwareMonitorLib` (`0.9.4`) передаёт JSON-снимки температур, частот, напряжений и вентиляторов через stdout.

## Основные модули

- **Обзор (Dashboard)** — загрузка CPU/RAM/GPU/диска, графики истории, маршруты и замер задержки с явным методом (`ICMP` / `TCP`).
- **Автозагрузка (Startup)** — реестр `Run`/`Run32`, `StartupApproved`, задачи планировщика, папка автозагрузки с проверкой reparse points и безопасным отключением/удалением.
- **Накопители и S.M.A.R.T. (Storage)** — категории, виртуализированное дерево каталогов, крупнейшие файлы и состояние физических накопителей. Размеры файлов логические, а проценты в дереве рассчитываются отдельно от размера родительского каталога и занятого места тома. Сканирование явно отмечает частичный результат.
- **Мониторинг железа и диагностика (Hardware)** — датчики LibreHardwareMonitor + fallback DXGI/PDH/IOCTL, анализ временных рядов и экспорт CSV.
- **Очистка (Cleanup)** — безопасная очистка временных каталогов, кэшей шейдеров, миниатюр и кэша браузеров с защитой куки/истории.
- **Процессы (Process Explorer)** — представления «Приложения», «По родителю» и «Список», завершение процесса/ветки с проверкой идентичности и приостановка потоков. I/O показывает ввод-вывод процесса по счётчикам Windows, включая операции вне физического диска. «Н/Д» означает ожидание второго замера, «Недоступно» — отсутствие доступа или счётчика. Ноль означает измеренный нулевой расход между выборками.
- **Сеть (Network)** — реальный RX/TX по интерфейсам, тест стабильности, UDP DNS-бенчмарк, MMCSS/EEE-оптимизация с сохранением оригинальных настроек и откатом.
- **AURORA Drop** — приём файлов и текста в локальной сети по QR или токену сессии. Передача идёт по HTTP без TLS.
- **Питание (Power Manager)** — серверный планировщик выключения/перезагрузки/сна Windows (`shutdown.exe` / WinAPI), устойчивый к закрытию окна в трей.
- **Скрипты и Архиватор (Scripts & Archive Creator)** — выполнение PowerShell/CMD/VBS (в том числе от Администратора) с захватом реального кода возврата и таймаутом; создание `.zip` и `.rar`.

## Используемые технологии и зависимости

- **Frontend:** Node.js 22.18+, TypeScript 6 (`~6.0.3`), React 19, Vite 8, Tailwind CSS 4, Framer Motion, Lucide React, `@tauri-apps/api`.
- **Backend:** Rust (Edition 2024), Tauri 2, `windows` crate (`0.62`), `sysinfo`, `winreg`, `rayon`, `jwalk`, `flate2`, `crc32fast`, `qrcode`, `png`, `serde`.
- **Sidecar:** .NET 10 LTS SDK (`net10.0`, `win-x64`), NuGet-пакет `LibreHardwareMonitorLib` `0.9.4`.

## Сборка

### Требования к окружению
- Windows 10 или Windows 11 (`x64`)
- Node.js 22.18+ (`npm` и встроенная обработка TypeScript для тестов)
- Rust toolchain (`stable-x86_64-pc-windows-msvc` + `rustfmt`)
- .NET 10 LTS SDK (`dotnet --list-sdks` содержит `10.0.x`)
- Visual Studio Build Tools C++ & WebView2 Runtime (стандартные пререквизиты Tauri 2 на Windows)

### Порядок сборки
1. Установка JS-зависимостей:
   ```powershell
   npm ci
   ```
2. Публикация C# sidecar (`win-x64`, single-file) и обновление ресурса `src-tauri/nexus-hwmon.exe`:
   ```powershell
   npm run build:sidecar
   ```
3. Проверка TypeScript и сборка Frontend (`dist/`):
   ```powershell
   npm run build
   ```
   *(Команда `npm run build:all` последовательно запускает `build:sidecar` и `build`.)*
4. Полная desktop-сборка Tauri (`beforeBuildCommand` автоматически вызывает `npm run build:all`, исключая упаковку устаревшего sidecar):
   ```powershell
   npm run tauri -- build --bundles nsis
   ```

Установщик находится в `src-tauri/target/release/bundle/nsis/`. Выпуск включает `aurora.exe`, иконку Windows и `aurora-hwmon.exe` рядом с основным файлом. Если Windows сообщает о занятом бинарном ресурсе при сборке, завершите отладочный экземпляр, который использует этот файл.

## Запуск тестов и проверок

- **Локальный запуск в Windows WebView2:**
  ```powershell
  npm ci
  npm run build:sidecar
  npm run tauri -- dev
  ```
- **Frontend unit-тесты (Node.js test runner):**
  ```powershell
  npm run test
  ```
- **Проверка форматирования и компиляции Rust:**
  ```powershell
  cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
  cargo check --manifest-path src-tauri/Cargo.toml
  ```
- **Rust unit-тесты (без жёсткой привязки к физическому оборудованию — безопасно для CI):**
  ```powershell
  cargo test --manifest-path src-tauri/Cargo.toml --lib
  ```
- **Аппаратные интеграционные тесты (только для физического ПК с реальным GPU/NVMe/NIC):**
  ```powershell
  cargo test --manifest-path src-tauri/Cargo.toml --lib -- --ignored
  ```

## Известные технические ограничения

- **HVCI (Целостность памяти / Memory Integrity) и права администратора:** доступность аппаратных датчиков зависит от оборудования, драйвера и политики Windows. Температура пакета CPU отображается при наличии отдельного датчика пакета. Температуры ядер отображаются отдельно, а интерфейс различает отсутствие показаний, подтверждённую блокировку драйвера и устаревший замер. DXGI, Windows PDH и NVMe IOCTL / PowerShell продолжают предоставлять доступные им показатели. [Документация Microsoft о блокировке драйверов](https://learn.microsoft.com/en-us/windows/security/threat-protection/windows-defender-application-control/microsoft-recommended-driver-block-rules)
- **Повышение прав при запуске скриптов (UAC):** интерактивный запрос UAC (`-Verb RunAs`) требует присутствия пользователя в сеансе Windows; автоматическое тестирование в headless/CI без UI ограничивается запуском и проверкой wrapper-логики без обхода UAC.
- **Классический ZIP (без Zip64):** встроенный ZIP-архиватор поддерживает стандартный 32-битный формат (до 65 535 записей и до 4 ГБ на файл и общий объём). Для больших наборов используется формат `.rar`.
- **Формат RAR:** создание `.rar` требует установленного WinRAR (`Rar.exe` / `WinRAR.exe`); при его отсутствии функция честно сообщает об ошибке и не создаёт поддельные архивы.
- **Платформа:** приложение предназначено только для Windows x64; на CI-раннерах без физического NVMe/дискретного GPU/физической сетевой карты соответствующие аппаратные проверки помечены атрибутом `#[ignore]` и не ломают базовую сборку.
